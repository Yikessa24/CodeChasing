为什么做 CodeChasing

复现一篇论文，意味着在 PDF 和编辑器之间反复横跳，还要时刻怀疑 AI 给出的页码和行号是不是编的。

用通用 AI 聊天读论文

  • 引用靠模型记忆生成，页码、行号可能是幻觉
  • 论文与代码割裂在两个窗口，对照全靠手工
  • 扫描版 PDF、架构图、公式截图无法理解
  • 整个仓库丢进上下文，隐私与成本都失控

CodeChasing 的方式

  • 引用只允许指向本轮真实提供的证据，双重审计把关
  • 论文 ↔ 代码双向跳转，映射关系可审核、可持久
  • 扫描页自动 OCR，图表以页面图像交给视觉模型
  • 索引与检索全部本地，默认不发送仓库代码

核心功能

围绕「证据」构建的六项能力，全部在 VS Code 内完成。

真实可点击的引用

论文锚点内容寻址，保存哈希、页码与高亮快照，PDF 重新处理也不会悄悄改指向；代码锚点来自编辑器选区或符号扫描。无效 ID 与冲突数字在展示前移除。

Agentic 自主探索

模型用本地 search / read 工具迭代探索代码库与整篇 PDF，默认最多 8 轮、可配置到 20 轮。只有实际读到的摘录进入回答上下文，并可被引用。

论文 ↔ 代码映射图

只从同一句话本地共引论文与代码的证据中学习映射，按工作区持久化；代码或 PDF 变更后自动标记失效，用户可逐条确认或拒绝。

张量形状符号推导

对 reshape、permute、归约、广播、Linear、Conv、Embedding、einsum 等常见操作做保守符号传播；running example 跨轮次持久保存、增量合并。

视觉理解与 OCR

准备阶段自动检测扫描页并 OCR 成可检索证据；架构图、曲线、表格、公式按页面图像发给视觉模型，回答与审计时再次附上原图。

隐私优先

PDF 提取、检索、符号扫描全部本地；API key 按提供商与端点隔离存入 SecretStorage；自主探索排除 .env、私钥与凭据文件；普通聊天默认不检索仓库代码。

工作原理：一条证据流水线

从 PDF 像素到可点击引用，每一步都在本地留下可验证的痕迹。

  1. 01本地提取PDF.js 文本 + 精确坐标
  2. 02内容寻址锚点段落 / 标题 / 图表 / 公式
  3. 03检索与探索问题驱动的有限轮次读写
  4. 04模型回答仅使用本轮提供的证据
  5. 05双重引用审计确定性校验 + 语义审计
  6. 06可点击证据跳回论文高亮 / 代码行

1 · 本地证据准备

导入 PDF 后在后台提取文本与高亮坐标，无需打开阅读器；语言服务器扫描工作区符号，静态分析构建带置信度分级的调用图。扫描页在此阶段完成 OCR。

2 · 有界探索回答

整篇论文请求会读取全部页面；精确章节或段落请求直接定位邻近页面。代码侧支持从选区动态扩展调用者与被调用者，跨模块追踪发现。

3 · 审计后才展示

确定性检查引用 ID、来源范围与数字一致性，可选语义审计判断引用是否真的支撑结论；审计不可用时回退确定性校验而非静默删除。缺少锚点的草稿会自动重写一次。

扩展架构

VS Code extension
├── Assistant Webview          对话界面（Markdown / KaTeX / 流式输出）
├── PDF.js paper viewer        本地打包的阅读器与文本层
├── PaperStore                 工作区本地论文工件
├── RepositoryIndex            符号、行范围与静态调用图
├── SemanticMappingStore       可审核的论文 ↔ 代码映射图
├── Running example & shapes   持久化示例与符号形状追踪
├── Hybrid retrieval           轻量混合证据检索
└── Provider adapters          OpenAI-compatible / Anthropic / Gemini

技术与工程

一个人、48 个版本——靠的是严格的发布门禁，而不是运气。

技术栈

  • TypeScript
  • VS Code Extension API
  • PDF.js 6.2.108（本地 WASM）
  • KaTeX（本地打包）
  • esbuild
  • Node.js 22+

无 CDN 依赖，公式渲染与 PDF 解析全部离线可用；升级 PDF.js 修复了恶意 PDF 任意脚本执行的高危漏洞。

模型支持

  • OpenAI-compatible
  • Anthropic
  • Gemini

兼容 Ollama、LM Studio 等本地端点；六档推理强度按协议映射（reasoning_effort / output_config.effort / thinkingLevel）；三家协议均支持图像输入。

质量门禁

每次发布执行 npm run check：类型检查 + Webview 语法检查 + 回归测试 + 构建。回归场景覆盖流式中断、取消、断网、UTF-8 分片、重复提交与引用恢复；冒烟测试解析真实的多页论文。

获取与体验

CodeChasing 是 VS Code 扩展，本站是它的展示窗口；源码与完整文档在 GitHub 公开仓库。

环境要求

  • VS Code 1.101+
  • Node.js 22.13+

从源码运行

git clone https://github.com/Yikessa24/CodeChasing.git
cd CodeChasing
npm install
npm run check   # 类型检查 + 测试 + 构建

在 VS Code 中打开目录并按 F5，扩展开发宿主窗口即可体验。

上手四步

  1. 齿轮图标配置模型提供商、Base URL、模型与 API key，并用连接测试验证。
  2. 把 PDF 拖进对话（或点 + 上传），后台完成本地准备。
  3. 搜索图标扫描工作区符号；选中代码按 Cmd/Ctrl+Alt+P 提问或追踪。
  4. 点「从论文到代码」开始 guided walkthrough；点击 [P…] / [C…] 引用跳回证据。
